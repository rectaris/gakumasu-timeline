# レビュー観点

このドキュメントは、AI / 保守作業者が修正点探索やレビュー時に確認する観点をまとめたものです。

## 機能

- 描画・可視判定が `displayStartDay` / `displayEndDay` に揃っているか
- `singleWithinRange` が具体的な発生日のように誤読されないか
- 共通イベントの複製表示で `instanceId` が衝突していないか
- URL の `event` が `canonicalId` と整合しているか
- フィルタ変更後に見えないイベントの詳細が残らないか

## 入力操作

- ホイールで水平拡大縮小できるか
- 横方向ホイールで左右移動できるか
- ドラッグで上下左右移動できるか
- ドラッグ後の誤クリック抑止が過剰でも不足でもないか
- `Escape` がメニュー / マニュアル / パネルを閉じられるか

## UI

- 年月日ラベルが固定表示のまま縦移動に追従しているか
- 共通イベント、通常イベント、`singleWithinRange` の見た目が区別できるか
- 画面全体表示で左右端や下部レーンが見切れないか
- メニューと詳細パネルが重なっても操作不能にならないか

## 重複と残骸

- 同じ描画ロジックや派生計算が複数ファイルに複製されていないか
- 未使用の `prop`、`computed`、関数、CSS が残っていないか
- 旧 UI のスタイルやヘルパーが残っていないか

## ドキュメント

- `README.md`
- `docs/manual.md`
- `docs/ui-behavior.md`
- `docs/processing-flow.md`

UI や表示を変えた場合は `docs/manual.md` を更新対象として必ず確認します。
それ以外のドキュメントは、変更内容と既存記述を照らし合わせて必要なものを更新します。

## 報告方針

- 問題点は、許す限り多く拾う
- わかりやすく、正確に説明する
- 重複処理や未使用コードも、低優先度として埋もれさせずに報告する
- 重大度順で報告する
- アイテマイズを使い、`1.` から番号を振る
- 各項目に重要度を明記する

## 修正後の報告

- 変更点
  - 変更内容
  - 問題
  - 解決策
- 確認結果
  - `npm run build`
  - 実機確認の有無
- 未確認リスク
  - 未確認の環境や操作
