# 広告実装方針メモ

このドキュメントは、`gakumasu-timeline` に広告機能を入れる場合の方針を整理したメモです。  
現時点では **AdSense 審査待ちのため実装を凍結中** とし、明示的な再開指示があるまで広告実装は進めません。

## 現在の前提

- `rectaris.github.io` は入口用のポータルとして利用する
- `gakumasu-timeline` は引き続き project site として公開する
- 広告は操作感を落とさないことを最優先とする
- Auto ads は使わず、手動配置の ad unit を前提とする

## 凍結条件

- AdSense の site review が未完了の間は、広告表示の実装を進めない
- review 完了前は、説明・設計・差分案の整理までに留める
- 再開時も、実装前に配置位置と影響範囲を確認する

## 再開条件

広告実装を再開するのは、次の条件を満たした後とする。

1. AdSense 審査が完了している
2. どの site 単位で広告配信するかが確定している
3. ユーザーから広告実装再開の明示指示がある

## 採用方針

### 配置

- 広告は **タイムライン内容の最下部** に 1 枠だけ配置する
- タイムラインのスクロール内容に含め、通常は末尾まで見た時に現れる位置へ置く
- 表示レーンが少ない場合でも、広告枠が途中まで上がらないよう上側の空きを伸ばして下部寄せを維持する
- タイムライン本体、イベント上、ドラッグ面の上には重ねない

### 表示方式

- `Display ad unit`
- `Responsive`
- `Auto ads` は使わない
- overlay / anchor 的にタイムライン本体へ重ねる表示は採用しない

### 操作感の制約

- ドラッグ操作を妨げない
- ホイール拡大縮小を妨げない
- タップやクリックの誤爆を増やさない
- タイムライン描画領域の hit area を侵食しない

## 非採用方針

- タイムライン上へのオーバーレイ広告
- イベントカードや詳細パネル内への常設広告
- 自動配置で位置制御が弱い広告方式
- review 完了前の広告コード本実装

## 実装再開時の想定構成

追加候補:

- `src/composables/useAds.js`
- `src/components/ads/AdSlot.vue`
- `src/components/timeline/TimelineAdFooter.vue`

変更候補:

- `index.html`
- `src/App.vue`
- `src/composables/useTimelineLayout.js`
- `src/style.css`

## 実装再開時の順序

1. AdSense review 状態の確認
2. ad unit の種類と slot ID の確定
3. タイムライン末尾広告のレイアウト差分作成
4. 実装
5. `npm run build`
6. 実機ブラウザ確認
7. 必要な `README.md` / `docs/` 更新

## 実装時の確認観点

- タイムライン末尾広告が、レーン数が少ない時も途中まで上がらず下部に収まるか
- タイムライン操作中に広告が誤タップされないか
- モバイルで広告が過剰に高さを取らないか
- 広告非表示時と表示時でレイアウトが破綻しないか
- AdSense 読み込み失敗時でも UI が壊れないか

## エージェント向け注意

- この方針は「今すぐ広告を実装する」指示ではない
- 広告関連タスクでは、まずこのドキュメントを確認する
- review 未完了ならコード変更ではなく設計整理に留める
- 実装を再開する場合は、ユーザーの合意を取ってから進める
