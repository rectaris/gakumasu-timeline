# 物語時系列のデータ作成

- 状態：Draft
- 仕様バージョン：0.1

## Source of Truth

rawデータ、生成物、編集画面、手動編集の責務を定義します。

## 作成手順

レーン選択、ID発行、時期入力、参加者と世界線の参照、出典登録、生成、検証の順序を定義します。

Curiretasの公開画面では、`contributor` または `admin` のロールを持つログイン済みアカウントに「イベントを投稿」を表示します。

`contributor` は、タイムラインD1の有効な付与、または現在のDiscordサーバー所属から対応付けたrole IDのどちらかで有効になります。

Discord由来の権限はリクエストごとにアカウントWorkerの非公開RPCで確認し、タイムラインD1へ保存しません。

投稿画面は既存レーンへのイベント追加を受け付け、既存のworldline検証と同じ構造・意味検証をWorkerで実行します。

投稿はタイムライン用D1へ `submitted` 状態で保存され、raw JSONを直接変更しません。

投稿者は自分の申請だけを確認できます。

## 出典

表示用ラベル、構造化出典、StoryBlock参照、外部URLの使い分けを定義します。

## 不確実な情報

推定、範囲、矛盾、未確認、出典なしを記録するときの基準を定義します。

## レビュー

通常追加、意味変更、時系列解釈変更、公開ID変更の承認境界を定義します。

`reviewer` または `admin` のロールを持つアカウントは、審査待ち申請を一覧し、承認または却下できます。

`reviewer` もタイムラインD1の有効な付与、または現在のDiscordサーバー所属から対応付けたrole IDで有効になります。

`admin` はDiscordから付与せず、タイムラインD1の有効な付与だけを使用します。

Discordの確認に失敗した場合はDiscord由来の権限を付与せず、独立して有効なタイムラインD1の付与だけを使用します。

審査は `submitted` から `approved` または `rejected` への1回だけの遷移です。

別の審査者が先に更新した場合は競合として扱い、最新のキューを読み直します。

投稿者ID、審査者ID、付与者ID、失効者IDと各時刻はD1の監査項目として保持します。

クライアントが送るアカウントIDは本人性の根拠にせず、Workerが `ACCOUNT_SERVICE` 経由で取得したアカウントIDだけを操作主体に使います。

### Gitへの反映

`approved` は「リポジトリへ反映してよい」という審査結果であり、公開完了を意味しません。

審査者または編集者は承認済み申請の `target_lane_id` と `payload_json` を確認し、対応する `data/raw/worldline_commu/` のJSONへ手動で反映します。

反映後は次の検証を行い、差分を通常のGitレビューとcommitへ進めます。

```sh
npm run generate:data
npm run validate:data
npm run test
npm run build
```

D1から `src/data/generated/` や公開アセットへ自動反映する処理はありません。

公開のsource of truthはGit管理されたraw JSONです。

## 検証

focused validation、全体検証、生成物差分、ブラウザ確認の必要条件を定義します。

投稿APIの変更では、セッション検証、ロール、IDOR、Origin、入力上限、状態遷移、同時審査、監査項目のWorkerテストを実行します。

投稿・審査UIの変更では、匿名、投稿者、審査者、障害時、狭い画面の各状態を確認します。
