# 物語イベントのデータモデル

- 状態：Draft
- 仕様バージョン：0.1

## 対象

この文書は、物語イベントグラフを構成する保存データと表示時の派生データを定義します。

## エンティティ

### StorySeries

StoryBlockを分類するカテゴリ、シリーズ、章などの階層を表す契約を定義します。

シリーズや章は分類情報であり、グラフ上のノードにはしません。

初期対象の階層は次のとおりです。

- アイドルコミュ
  - アイドルごとに分類します。
  - 親愛度はSTEP1、STEP2、STEP3、STEP4に分類し、各話は「親愛度 第○話」の形式で表します。
  - プロデュースは育成、授業、おでかけ、営業に分類します。
  - プロデュースの育成は定期公演『初』、NEXT IDOL AUDITION、Hatsuboshi IDOL FESTIVALに分類します。
  - Pアイドルは「[楽曲]アイドル名」の形式で分類します。
- イベントコミュ
  - イベントごとに分類し、各話は「イベント名 第○話」の形式で表します。
- サポートコミュ
  - サポートカードごとに分類し、各話は「サポカ名 サポカコミュ名」の形式で表します。
- 初星コミュ
  - コミュごとに分類し、各話は「コミュ名 ○章 ○話」の形式で表します。

### StoryBlock

ゲーム内で1つのコミュとして存在する「話」を表します。

各StoryBlockは、安定ID、表示名、カテゴリ別階層、話番号、人物タグなどを持てます。

同じ話を人物別に複製しません。

### StoryEdge

接続元、接続先、方向、関係種別、表示ラベル、根拠、確度の契約を定義します。

### EvidenceLink

「物語時系列」または「学マス情報史」の要素からStoryBlockを参照する契約を定義します。

参照の所有場所と多重度は未決定です。

## ID

系列、ノード、エッジ、EvidenceLinkの名前空間と公開後の互換性を定義します。
日本語の表示名だけから正規IDを生成しない規則を定義します。

## 物語上の順序

StoryBlockには物語内時刻や現実世界の日時を保持しません。

物語上の時系列は、ノードの前後関係と相対的な間隔で表します。

画面上のピクセル距離を保存データとするかどうかを含め、相対間隔の保存方式は未決定です。

## 保存データと派生データ

手動登録する関係と、カテゴリ別階層や話番号から生成できる関係を区別する必要があります。

具体的な境界はエッジ仕様の検討時に決定します。

## 検証

一意性、参照整合性、カテゴリ別階層、方向、関係種別、自己エッジ、並列エッジ、相対順序の検証条件を記載します。

## 未決定事項

- StorySeriesとStoryBlockを保存するファイル粒度。
- カテゴリ別階層を単一の共通構造とするか、カテゴリ別の構造とするか。
- STEPや章をまたぐ話番号の識別規則。
- 相対的なノード間隔の保存方式。
- EvidenceLinkを参照元とStoryBlock側のどちらで所有するか。
