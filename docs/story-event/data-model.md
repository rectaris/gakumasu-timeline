# 物語イベントのデータモデル

- 状態：Draft
- 仕様バージョン：0.1

## 対象

この文書は、物語イベントグラフを構成する保存データと表示時の派生データを定義します。

## エンティティ

### StorySeries

StoryBlockを分類するカテゴリ、シリーズ、章などの階層を表す契約を定義します。

シリーズや章は分類情報であり、グラフ上のノードにはしません。

StorySeriesには不変IDを発行し、StoryBlockから参照します。

StoryBlockの共通フィールドとカテゴリ固有の構造化情報を分け、カテゴリごとの入力規則を検証できる形にします。

初期対象の階層は次のとおりです。

- アイドルコミュ
  - アイドルごとに分類します。
  - 親愛度はSTEP1、STEP2、STEP3、STEP4に分類し、各話は「親愛度 第○話」の形式で表します。
  - プロデュースは育成、授業、おでかけ、営業に分類します。
  - プロデュースの育成は定期公演『初』、NEXT IDOL AUDITION、Hatsuboshi IDOL FESTIVALに分類します。
  - Pアイドルは「[楽曲]アイドル名」の形式で分類します。
- イベントコミュ
  - イベントごとに分類し、各話は「イベント名 第○話」の形式で表します。
- サポートコミュ
  - サポートカードごとに分類し、各話は「サポカ名 サポカコミュ名」の形式で表します。
- 初星コミュ
  - コミュごとに分類し、各話は「コミュ名 ○章 ○話」の形式で表します。

### StoryBlock

ゲーム内で1つのコミュとして存在する「話」を表します。

各StoryBlockは、不変ID、正式な表示名、StorySeries参照、カテゴリ別の構造化情報、人物参照などを持ちます。

人物参照には、`owner`、`focus`、`participant`の役割を付けられます。

同じ話を人物別に複製しません。

内容が同一でも、ゲーム内で別のコミュとして管理されている場合は別のStoryBlockとします。

同じゲーム内コミュを別の場所から閲覧できるだけの場合は、別名または外部識別子として同じStoryBlockへ対応付けます。

### StoryEdge

1つの論理エッジとして、次の情報を保持します。

- 不変ID。
- 接続元StoryBlock ID。
- 接続先StoryBlock ID。
- `sequence`または`semantic`のエッジ種別。
- `undirected`、`forward`、`bidirectional`の方向。
- 制御されたrelationType。
- 任意の表示ラベル。
- 必要に応じた根拠と確度。

### EvidenceLink（仮称）

「物語時系列」または「学マス情報史」の要素からStoryBlockを参照する型付き契約を定義します。

参照元のデータがStoryBlock IDと参照種別を保持します。

StoryBlockから参照元を列挙する逆引き情報は、保存データへ重複させずに生成します。

## ID

系列、ノード、エッジ、EvidenceLinkには、プロジェクトが管理する不変IDを発行します。

ゲーム内ID、旧名称、現在の表示名は、不変IDとは別の外部識別子または別名として保持できます。

日本語の表示名やカテゴリ階層だけから正規IDを生成しません。

## 物語上の順序

StoryBlockには物語内時刻や現実世界の日時を保持しません。

物語上の時系列は、`sequence`エッジによる単純な前後関係だけで表します。

ノード間距離、エッジの長さ、画面座標には時間的な意味を持たせません。

## 保存データと派生データ

カテゴリまたはシリーズ単位で編集用の原データを保存し、表示用の索引を生成します。

話番号などから生成できる`sequence`エッジと、手動登録する`semantic`エッジを区別します。

## 検証

一意性、参照整合性、カテゴリ別階層、人物の役割、方向、関係種別、自己エッジ、並列エッジ、前後関係の循環を検証します。

## 未決定事項

- StorySeriesとStoryBlockを保存するファイル粒度。
- カテゴリ別構造化情報の具体的なフィールド名と型。
- STEPや章をまたぐ話番号の識別規則。
- IDの名前空間、書式、発行手順。
- ビューごとの参照種別と多重度。
- EvidenceLinkを汎用的なビュー間参照に改称するかどうか。
