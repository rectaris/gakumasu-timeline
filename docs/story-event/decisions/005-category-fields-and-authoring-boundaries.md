# カテゴリ別フィールドとデータ作成境界

- 状態：Accepted
- 決定日：2026-07-19
- 対象仕様バージョン：0.1

## 背景

アイドルコミュ、イベントコミュ、サポートコミュ、初星コミュでは必要な階層が異なります。

人物情報、外部識別子、ファイル分割、既存`source`文字列からの移行方法も、検証可能な形で統一する必要がありました。

## 決定

- StoryBlockの共通フィールドを最小限とし、カテゴリ固有の規則はStorySeriesの`category`と`kind`の組み合わせで検証します。
- PアイドルをStorySeriesとし、その配下にあるゲーム内の各コミュをStoryBlockとします。
- StoryBlockの`episodeOrder`はゲーム内での表示順を表し、物語上の前後関係には使用しません。
- 1人の人物に`owner`、`focus`、`participant`の複数の役割を付与できます。
- アイドルコミュでは`owner`を1人要求し、他のカテゴリでは要求しません。
- 外部識別子は`system`、`type`、`value`を持つ型付きデータとし、表示上の別名と分離します。
- 編集用原データはJSONとし、最上位または独立して編集するStorySeriesごとに1ファイルへ保存します。
- 一覧、検索索引、階層展開結果、逆引き参照は原データから生成します。
- 既存`source`文字列はレビュー済み対応表でStoryBlock IDへ対応付け、実行時には推定しません。

## 影響

- ファイルパスとファイル名はStorySeriesまたはStoryBlockの同一性として使用しません。
- カテゴリごとに許可するStorySeries階層を検証します。
- ID発行ツールと対応表の具体的なファイル形式は実装計画で定めます。
