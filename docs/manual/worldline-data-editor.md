# Worldline Data Editor マニュアル

このマニュアルは、開発用の Worldline Data Editor で worldline raw JSON を編集するための項目説明と操作方法をまとめたものです。

## 対象画面

- 起動条件: ローカル開発環境で `npm run dev` を実行していること
- URL: `/timeline/?editor=worldline`
- 例: `http://127.0.0.1:5174/timeline/?editor=worldline`

Worldline Data Editor は dev server 専用 API を使います。本番ビルドでは通常タイムライン画面を使います。

## 編集対象

永続的な source of truth は `data/raw/worldline_commu/` 配下の raw JSON です。
保存時には raw JSON と対応する `src/data/generated/` の生成済みデータが更新されます。

| コミュ種別 | raw JSON の場所 | 新規ファイル |
| --- | --- | --- |
| 共通コミュ | `data/raw/worldline_commu/common_timeline.json` | 不可 |
| アイドルコミュ | `data/raw/worldline_commu/idol_commu/*.json` | 可 |
| 初星コミュ | `data/raw/worldline_commu/hatsuboshi_commu/*.json` | 可 |
| イベントコミュ | `data/raw/worldline_commu/event_commu/*.json` | 可 |
| サポカコミュ | `data/raw/worldline_commu/support_story/*.json` | 可 |

新規ファイルを作成できるのは、ファイル付きカテゴリだけです。
共通コミュは単一ファイルのため、新規ファイル作成の対象外です。

## 画面構成

| 領域 | 説明 |
| --- | --- |
| 左サイドバー | コミュ種別、ファイル、イベント一覧、検索を操作します。 |
| 編集フォーム | 選択中イベントまたは新規イベントの各フィールドを編集します。 |
| ツールバー | 複製、削除、差分確認、保存を実行します。 |
| 保存前レビュー | 保存先、変更項目、プレビュー、検証結果、保存結果を確認します。 |
| レーンプレビュー | 保存先レーン内でイベントがどの時期に入るかを確認します。 |

各項目名にマウスオーバーまたはキーボードフォーカスすると、項目説明が表示されます。

## 左サイドバー

| 項目 | 説明 |
| --- | --- |
| 検索 | イベント一覧をタイトル、詳細、出典、ファイル名で絞り込みます。 |
| コミュ種別 | 左のイベント一覧に表示するカテゴリを選びます。 |
| ファイル | 表示対象ファイルを選びます。`すべて` を選ぶと、同じコミュ種別の全イベントを一覧できます。 |
| 新規イベント | 選択中ファイルへ追加する新規イベントの入力を開始します。 |
| イベント一覧 | 選択中コミュ種別とファイル条件に一致するイベントを表示します。 |

`ファイル` が `すべて` の場合、新規イベント追加は無効です。
新規イベントは具体的なファイルを選んでから作成します。

イベントを選択しても、`ファイル` が自動的に選択イベントのファイルへ切り替わることはありません。
`すべて` 表示のまま、選択イベントの内容だけがフォームへ読み込まれます。

## ツールバー

| 操作 | 説明 |
| --- | --- |
| 複製 | 選択中イベントをコピーして、新しい ID の下書きを作ります。類似イベントを追加する時に使います。 |
| 削除 | 選択中イベントを削除します。確認ダイアログが表示されます。 |
| 差分確認 | 保存せずに検証とパッチ表示を行います。保存前に必ず内容を確認します。 |
| 保存 | 保存先コミュ種別と保存先ファイルへ変更を反映します。保存時にも検証が実行されます。 |

保存先は、編集元ではなく `保存先コミュ種別` と `保存先ファイル` で決まります。
既存イベントを別ファイルへ保存すると、イベントの移動として扱われます。

## 基本情報

| 項目 | 説明 | 入力の注意 |
| --- | --- | --- |
| ID | 共有 URL や重複チェックに使う安定 ID です。 | 公開後の変更は共有 URL を壊すため避けます。 |
| 保存先コミュ種別 | 保存先の raw データカテゴリです。 | イベントの意味に合うカテゴリを選びます。 |
| 保存先ファイル | 保存先の raw JSON ファイルです。 | ファイル付きカテゴリでは `新規ファイル` も選べます。 |
| 新規ファイル名 | 作成する raw JSON ファイル名です。 | 英数字、ハイフン、アンダースコアを使います。`.json` は付けても付けなくても正規化されます。 |
| 新規レーン ID | 新規ファイルのレーン ID です。 | 表示レーンや参加者の識別に使う安定 ID にします。 |
| 新規レーン名 | 新規ファイルの表示名です。 | イベント一覧や保存先プレビューに表示されます。 |
| 新規レーン色 | 新規レーンとイベントの識別色です。 | 色は `#rrggbb` の形式で扱います。 |
| タイトル | タイムライン上と詳細パネルで表示するイベント名です。 | 短く、一覧で識別できる名前にします。 |
| 詳細 | イベントの内容説明です。 | 根拠から読み取れる範囲で具体的に書きます。 |

新規ファイルを作る場合、ファイル名、レーン ID、レーン名、色が揃うまで保存先レーンプレビューは表示されません。

## 時期

| 項目 | 説明 | 入力の注意 |
| --- | --- | --- |
| 発生形式 | 期間イベントか、候補範囲内のどこか1日のイベントかを選びます。 | `期間内の1日` は具体日が不明な場合に使います。 |
| 開始 | イベントの開始時期です。 | 年、月、日を数値で入力します。 |
| 終了 | イベントの終了時期です。 | 単日イベントでも開始と終了を入力します。 |
| 日付確度 | 日付が確定か推定か、範囲だけかを示します。 | 未指定の場合も表示側で派生されますが、判断できる場合は明示します。 |
| 範囲理由 | 日付が範囲になる理由を選びます。 | `singleWithinRange` の時だけ使います。 |

日付は実カレンダーではなく、アプリ内の抽象時系列です。
各月は31日換算で扱われます。

### 発生形式

| 値 | 表示名 | 説明 |
| --- | --- | --- |
| `singleWithinRange` | 期間内の1日 | 開始から終了までの範囲内のどこか1日に発生します。 |
| `continuous` | 期間 | 開始から終了まで継続するイベントです。 |

### 日付確度

| 値 | 表示名 | 説明 |
| --- | --- | --- |
| 空 | 未指定 | 表示側の既定値を使います。 |
| `confirmed` | 確定 | 日付または期間が確定しています。 |
| `inferred` | 推定 | 根拠から推定した時期です。 |
| `rangeOnly` | 期間内の1日 | 候補範囲だけが分かっている単日イベントです。 |

### 範囲理由

| 値 | 表示名 | 説明 |
| --- | --- | --- |
| 空 | 未指定 | 明示しません。 |
| `monthOnly` | 月のみ確定 | 月までは分かるが日付が確定していません。 |
| `sourceRange` | 出典範囲 | 出典上の候補範囲に基づきます。 |
| `chapterOrder` | 章/話数順 | 章や話数の順序から範囲を決めています。 |
| `relativeOrder` | 前後関係 | 他イベントとの前後関係から範囲を決めています。 |
| `unknown` | 不明 | 理由を分類できません。 |

## 分類

| 項目 | 説明 | 入力の注意 |
| --- | --- | --- |
| 根拠分類 | 時期や内容の根拠が明示か推定かを分類します。 | 明示根拠と推論が混在する場合は `混在` を使います。 |
| 出典状態 | 出典の確認状態や矛盾の有無を分類します。 | 矛盾がある場合は `矛盾あり` を選び、出典矛盾欄も記入します。 |
| 参加者 | イベントに直接関係する人物を選びます。 | 未登録人物や集団名は無理に仮 ID 化せず、補足に書きます。 |
| 世界線 | イベントが属する世界線を選びます。 | 未確定の世界線を表す仮 ID は作りません。 |

### 根拠分類

| 値 | 表示名 | 説明 |
| --- | --- | --- |
| 空 | 未指定 | 明示しません。 |
| `explicit` | 明示 | 出典で明示されています。 |
| `inferred` | 推定 | 出典から推定しています。 |
| `mixed` | 混在 | 明示情報と推定が混在しています。 |
| `unknown` | 未分類 | 分類できません。 |

### 出典状態

| 値 | 表示名 | 説明 |
| --- | --- | --- |
| 空 | 未指定 | 表示側の既定値を使います。 |
| `confirmed` | 確認済み | 出典で確認できています。 |
| `inferred` | 推定根拠 | 推定の根拠があります。 |
| `conflicting` | 矛盾あり | 出典同士に矛盾があります。 |
| `unreviewed` | 未確認 | まだ確認していません。 |
| `unsourced` | 出典なし | 出典がありません。 |
| `unknown` | 分類不能 | 状態を分類できません。 |

## 出典と補足

| 項目 | 説明 | 入力の注意 |
| --- | --- | --- |
| 簡易出典 | 簡易的な出典メモです。 | 1行1件で入力します。構造化出典がある場合も要約を残せます。 |
| 補足 | 判断理由、保留事項、補足情報です。 | 1行1件で入力します。機械判定用フィールドではありません。 |

新規データでは原則として出典を入れます。
出典なしの断定は避け、未確認の場合は出典状態や補足で分かるようにします。

## 構造化出典

構造化出典は、出典ごとの状態や主張を分けて管理するための繰り返し項目です。
`追加` で出典行を増やし、各行の `削除` で取り除きます。

| 項目 | 説明 | 入力の注意 |
| --- | --- | --- |
| ID | 構造化出典を識別する任意 ID です。 | 同一イベント内で重複しない ID にします。 |
| ラベル | 詳細パネルに表示する出典名です。 | 空の場合、その構造化出典は保存対象から除外されます。 |
| URL | 公式ページや資料など、確認元の URL です。 | URL がある場合だけ入力します。 |
| 状態 | この出典単体の確認状態です。 | 出典全体の状態とは別に、出典単位の状態を表せます。 |
| 主張 | この出典から読み取れる主張や根拠です。 | 出典が支える内容を自然文で書きます。 |
| 支える対象 | この出典が支えている対象です。 | イベント、日付、詳細、世界線、参加者から選びます。 |

### 支える対象

| 値 | 表示名 | 説明 |
| --- | --- | --- |
| `event` | イベント | イベントの存在や発生自体を支えます。 |
| `date` | 日付 | 時期や日付を支えます。 |
| `detail` | 詳細 | 詳細内容を支えます。 |
| `worldline` | 世界線 | 世界線分類を支えます。 |
| `participants` | 参加者 | 参加者情報を支えます。 |

## 出典矛盾

出典矛盾は、複数の出典や解釈が食い違う場合だけ入力します。
`追加` で矛盾行を増やし、各行の `削除` で取り除きます。

| 項目 | 説明 | 入力の注意 |
| --- | --- | --- |
| 概要 | 出典同士で食い違う内容の要約です。 | 空の場合、その矛盾行は保存対象から除外されます。 |
| 出典 | 矛盾に関係する出典です。 | 1行1件で入力します。 |
| 解決状態 | 現時点の採用判断や未解決理由です。 | 未解決の場合も、その理由を残します。 |

`conflicts` がある場合、出典状態は `矛盾あり` にします。

## 保存前レビュー

| 項目 | 説明 |
| --- | --- |
| 対象 | 解決済みの保存先 raw JSON ファイルです。 |
| 変更項目 | 現在フォームで変更されている主な項目です。 |
| イベントプレビュー | タイトル、詳細、開始/終了時期を短く確認します。 |
| レーンプレビュー | 保存先レーン内でのイベント位置を確認します。 |
| 検証結果 | `差分確認` の結果です。保存可能/保存不可、変更ファイル、パッチ、検証メッセージを表示します。 |
| 保存結果 | `保存` の結果です。保存可否、パッチ、検証メッセージを表示します。 |

### レーンプレビュー操作

| 操作 | 説明 |
| --- | --- |
| 左へ / 右へ | プレビュー範囲を左右へ移動します。 |
| 拡大 / 縮小 | プレビューの時間幅を変更します。 |
| 全体 | プレビュー範囲を全体へ戻します。 |
| ドラッグ | 横方向と縦方向へ移動します。 |
| ホイール | カーソル位置を基準に拡大/縮小します。 |

## 基本的な編集手順

1. `npm run dev` を起動します。
2. `/timeline/?editor=worldline` を開きます。
3. 左サイドバーで `コミュ種別` を選びます。
4. `ファイル` を選びます。全体確認だけなら `すべて` を選びます。
5. 既存イベントを編集する場合は、イベント一覧から対象イベントを選びます。
6. 新規イベントを追加する場合は、具体的なファイルを選び、`新規イベント` を押します。
7. 基本情報、時期、分類、出典、補足を編集します。
8. 保存先コミュ種別と保存先ファイルを確認します。
9. 必要なら `差分確認` を押し、パッチと検証結果を確認します。
10. 問題がなければ `保存` を押します。
11. 保存結果が `保存しました` になったことを確認します。
12. 通常タイムライン画面で表示を確認します。

## 新規ファイルを作成する手順

1. 保存先コミュ種別で、ファイル付きカテゴリを選びます。
2. 保存先ファイルで `新規ファイル` を選びます。
3. `新規ファイル名`、`新規レーン ID`、`新規レーン名`、`新規レーン色` を入力します。
4. イベントの各項目を入力します。
5. レーンプレビューに新規レーンが表示されることを確認します。
6. `差分確認` で作成される raw JSON と generated データの差分を確認します。
7. 問題がなければ `保存` します。

新規ファイル名は、対象ディレクトリ直下の `英数字・ハイフン・アンダースコア + .json` に制限されます。
サブディレクトリや `..` を含むパスは保存できません。

## 削除する手順

1. 左サイドバーで対象イベントを選びます。
2. ツールバーの `削除` を押します。
3. 確認ダイアログで対象イベント名を確認します。
4. 削除してよければ承認します。
5. 保存結果とパッチを確認します。

削除はイベント単位です。
レーンファイル自体は削除しません。

## 複製する手順

1. 左サイドバーで元にするイベントを選びます。
2. ツールバーの `複製` を押します。
3. ID がコピー用に変更された下書きになります。
4. タイトル、詳細、時期、出典などを必要に応じて編集します。
5. 保存先を確認して `差分確認`、`保存` の順に進めます。

類似イベントを作る場合でも、ID、出典、日付確度、参加者、世界線が元イベントのままでよいか必ず確認します。

## 保存時の検証

保存前と保存時には、既存のデータ検証が実行されます。
主な検証観点は次のとおりです。

| 観点 | 説明 |
| --- | --- |
| イベント ID | 重複や空 ID を避けます。 |
| 日付範囲 | 開始と終了の範囲が妥当か確認します。 |
| 発生形式 | `occurrenceType` が許可値か確認します。 |
| 参加者 | `src/data/characterCatalog.js` に存在する ID か確認します。 |
| 世界線 | `src/data/worldlines.js` に存在する ID か確認します。 |
| 空文字 | 配列内に空文字や空白だけの値が残っていないか確認します。 |
| 不確実性メタデータ | `dateConfidence`、`sourceBasis`、`sourceStatus`、`rangeReason` の組み合わせを確認します。 |
| 構造化出典 | ラベル、ID 重複、支える対象の許可値を確認します。 |
| 出典矛盾 | `conflicts` と `sourceStatus` の整合を確認します。 |

エラーが出た場合は、検証メッセージに表示されるファイル、レーン、イベント、フィールドを確認して修正します。

## 作業後の確認コマンド

通常は保存時に生成まで実行されますが、手動確認では次を使います。

```bash
npm run validate:data
npm run test
npm run build
```

単一ファイルだけ確認したい場合は、次のように raw JSON のパスを指定します。

```bash
npm run validate:data -- data/raw/worldline_commu/idol_commu/001hanamiSaki.json
```

## 注意事項

- 公開後のイベント ID 変更は共有 URL を壊すため、原則として避けます。
- 具体日が不明なイベントに架空の確定日を入れないでください。
- 未登録人物や未確定世界線を仮 ID として追加しないでください。必要な情報は補足へ自然文で残します。
- 出典があるイベントに `出典なし` を付けないでください。
- 出典矛盾があるイベントでは、出典状態と出典矛盾欄の両方を整合させてください。
- 編集画面は raw JSON を直接更新するため、保存前に差分確認を行ってください。
